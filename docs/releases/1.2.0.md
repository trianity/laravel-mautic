# Laravel Mautic 1.2.0

Laravel Mautic 1.2.0 adds durable multi-segment membership plans while preserving the 1.1
single-segment delivery API and persisted intents.

## Highlights

- Record canonical present and absent segment requirements with
  `SubscriptionDelivery::recordPlan()`.
- Resolve every static target before mutation, remove absences before adding presences and
  verify each mutation plus the final plan.
- Retain per-target partial progress and require explicit operator recovery for ambiguous
  remote outcomes; successful earlier mutations are not rolled back.
- Order legacy and plan deliveries by the persisted contact revision so unresolved older
  work cannot be bypassed.
- Preserve existing `SubscriptionTransport` implementations for legacy work. Custom
  transports opt into plan removal through the additive `MembershipPlanTransport` contract.
- Keep `guzzlehttp/guzzle` at `^7.9`; this release does not include experimental Mautic SDK
  overrides or claim Guzzle 8 support.

## Upgrade requirement

Stop or drain all 1.1 subscription and contact-outbox workers, deploy 1.2 everywhere, publish
and run `mautic-subscription-migrations`, then restart workers. Enable `recordPlan()` only
after `2026_11_05_000000_add_mautic_subscription_membership_plans` has run on the configured
subscription database and no 1.1 worker remains. Existing legacy intents are retained and
continue in their original order. See [the upgrade guide](../UPGRADING.md).

## Verified for this candidate

- The default deterministic suite, formatting, strict Composer validation and Larastan level
  8 pass on the preferred local stack.
- The pre-handoff runtime commit `822ec87` passes GitHub Actions on PHP 8.4 and 8.5 with
  Laravel 12/Pest 4 and Laravel 13/Pest 5. Every matrix job resolves and asserts Guzzle 7
  before running the test suite.
- A disposable MariaDB 11.8.6 upgrade from the published 1.1 package preserved a pending
  legacy intent, applied only the forward migration and completed ordered legacy plus mixed
  plan work. The separately gated four-process MariaDB subscription scenarios also pass.
- A separately authorized disposable Mautic 7.2.1 OAuth acceptance completed a mixed removal
  and addition, preserved an unrelated membership and the exact manual email DNC entry, and
  proved idempotent replay without another mutation.

These checks are scoped evidence, not blanket compatibility claims. They did not test a
production host, host-specific business rules, campaign execution or mail delivery. No tag,
GitHub release, Packagist publication or clean install from a published 1.2 artifact was
performed while preparing this candidate.
The final documentation, archive rules and compatibility regression in the review worktree
were not committed or pushed, so no remote CI run exists for that exact final worktree yet.
